# Game API 与双语言绑定

## 单一来源

`Game` 的全部能力——方法名、参数、返回值、结果码、文档说明——只在 `crates/api` 中以 Rust 类型定义一次。由此生成：

| 产物 | 用途 |
| --- | --- |
| PyO3 绑定 | Python 侧 `Game` 及对象类型 |
| rquickjs 绑定 | JS 侧 `Game` 及对象类型 |
| TypeScript 声明 | 编辑器类型提示与检查 |
| Python 类型存根（.pyi） | 编辑器类型提示与检查 |
| 编辑器补全数据 | `Game.` 后的能力列表与悬浮文档 |
| API 参考文档 | 一份文档两语言共用，对齐玩法设计"文档与教程一份两用" |

接口命名与签名以 [API 设计基线](../game-design/08-api-design.md) 为准：两种语言同名 snake_case，JS 以选项对象传递关键字参数。接口签名与结果码从该处生成；语言容器、数字和生命周期语义仍须显式适配。同源生成是防漂移的工具，双语言语义一致的最终保障是黑盒一致性测试套件（见 [08](08-validation.md)）。

## 纯数据边界

跨越运行时边界的数据只有：id、整数、浮点、字符串、布尔、结果码常量、坐标及由这些值组成的数据记录和序列。不传递语言对象、闭包或存活引用。

- 查询返回的视图对象（Robot、Shelf、Order 等）由宿主本地查询镜像（tick 起世界视图 + 已回放的管理操作增量，见 [03](03-player-runtime.md)）构造，只读；世界字段值是构造时的拷贝，持有它们不延长模拟对象生命周期。`Robot.memory` 是明确的例外：它返回主进程受控数据树的访问句柄，不是可变世界视图。
- 动作与管理操作以 id 寻址；凡接受 id 的参数同样接受对象本身（取其 id）。
- 金额、价格、欠款等经济值在 API 上暴露为普通数字，由内部定点整数换算（表示见 [02](02-simulation-core.md)）；权威判定（扣款、限额、余额比较）一律在 `sim` 内以定点整数完成。玩家侧浮点运算可能与权威值差一个舍入位，文档与教程提示不要用浮点等值比较做资金判断。
- 跨边界不传原生指针；对象 id 与 memory 句柄分别校验存活性，存档编码由 [06](06-persistence.md) 定义。运行时可替换性以契约测试为准。

## 对象与寻址

遵循 [API 设计基线](../game-design/08-api-design.md)：

- id 为全局自增整数，跨类型唯一，顺序即创建顺序，也是冲突裁决的优先级依据。
- `Position` 为值对象：Python 实现为具名元组（支持解构、下标、等值比较、作字典键），JS 实现支持 `equals` / `adjacent` / `distance` / `neighbors`；序列化为 `[x, y]`。
- 跨对象引用字段（`holder`、`docked_vehicle` 等）一律为 id，经 `Game.get_object_by_id` 解析。

## 结果码

- 大写蛇形字符串，比较统一使用 `Game.E` 常量，受理 / 结算 / 管理共用一套词表（反馈模型见 [Tick、动作与电力](../game-design/03-simulation-and-actions.md)）。
- 词表在 `crates/api` 中与接口同源定义，随绑定一起生成到两种语言。

## 生成范围与语义适配

先用移动、查询、接单与嵌套 memory 修改打通双语言最小绑定，再扩展生成器。签名、结果码、类型存根与参考文档同源；Position、受控容器、参数转换、错误映射及 move_to 复合逻辑需要适配实现和共享测试，不能用“同源生成”代替语义证明。

memory 值模型以 [06](06-persistence.md) 为唯一权威；尤其测试插入原生容器后的别名隔离、数字字符串键顺序、嵌套修改与失效句柄。`move_to` 的路径缓存只在实际位置前进后消费；玩家手动移动导致当前位置偏离缓存时重新寻路，不按受理成功提前弹出路径。
