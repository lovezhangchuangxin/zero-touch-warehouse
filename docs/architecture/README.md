## 已定决策

- 技术栈：Tauri 2 + Rust + Vue 3 + TypeScript + Pixi.js（WebGL）。
- 双原生进程：主进程持有世界状态与结算；玩家代码在独立的宿主进程（runtime host）中执行，可随时终止重启。玩家代码的任何故障（死循环、吞中断、崩溃）都不导致进度回档，回档只发生在主进程自身崩溃时；webview 是纯视图层。
- 双语言运行时均为进程内嵌：JavaScript 走 rquickjs（内嵌 quickjs-ng），Python 走 PyO3（内嵌 CPython）。
- Game API 在 Rust 中单点定义，生成双语言绑定、类型存根、编辑器补全与文档。
- 沙箱目标是资源可控（内存、执行时间、能力面），不防恶意攻击（理由见 [03](03-player-runtime.md)）。
- 普通全局变量只跨 tick 保留；跨热重载（玩法设计称"代码重载"）与读档持久的只有 `Game.memory`。
- 目标平台仅 Windows 与 macOS 的主流版本，不支持 Linux（含 Steam Deck）。

## 架构原则

1. **世界状态唯一权威在 Rust**。前端只读渲染，玩家代码只能通过 Game API 访问。
2. **确定性**：同一平台、同一存档、同一份玩家代码、同一版本，模拟结果可复现。
3. **失败可解释**：一切超限与异常都转为玩家可读的错误并暂停世界——已受理的动作照常结算、推进到 tick 边界后暂停（见 [03](03-player-runtime.md) 故障分级）。
4. **双语言零漂移**：一份 API 定义生成两种语言的全部制品，名称与语义一致。
