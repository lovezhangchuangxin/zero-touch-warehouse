# 界面与渲染

## 职责划分

| 层 | 负责 |
| --- | --- |
| Pixi.js（WebGL） | 仓库网格、机器人、货物、车辆、路径与选中框等画布内容 |
| Vue 3 | 市场面板、商店、订单、机器人状态、日志、代码编辑器、调试器等 DOM 界面 |

Pixi 对象不进入 Vue 响应式系统，画布内容不通过 Vue 组件渲染。

## 渲染节奏

- 逻辑 tick 与 `requestAnimationFrame` 完全分离：世界线程按模拟速率推进，前端按显示器帧率渲染。
- 相邻快照之间对机器人位移做插值；暂停与单步时不插值，直接显示精确逻辑位置——调试时所见即模拟状态。
- 快进时每渲染帧合并多个 tick 的快照，取最新状态渲染。
- 首版固定 WebGL，不启用 WebGPU：两个内核的 WebGPU 支持与行为尚需逐版本验证，首版不依赖。

## 与 Rust 的通信

| 方向 | 通道 | 内容 |
| --- | --- | --- |
| Rust → 前端 | Tauri channel + 游标分页 command | 最新渲染快照独立推送；诊断事件按游标读取和确认 |
| 前端 → Rust | Tauri command | 界面命令：管理操作（购买、销毁）与会话控制（暂停、变速、存档） |

- Tauri command 一律异步实现，不得在主线程阻塞等待世界线程——世界线程挂起时窗口必须保持响应（见 [03](03-player-runtime.md) 故障分级）。
- 界面命令经指令队列进入世界线程串行执行；运行中在下一 tick 边界生效，暂停安全点立即生效，单步执行期间排到 tick 结束，时点与顺序规则见 [02](02-simulation-core.md)。
- 界面管理命令与玩家代码的管理操作共用同一 API 入口。
- 美术资产沿用图集方式（见 [美术资产](../art/atlas-v4.md)），运行时按图集加载。

## 代码编辑器

- 编辑器内核已选型 CodeMirror 6（2026-09 定）：按包体、Python 高亮与缩进质量、嵌入定制成本、双语言一致的补全注入四条标准比对，Monaco 排除。
- 补全、悬浮文档、类型提示全部由数据驱动（见 [04](04-api-bindings.md)），编辑器只做展示。目标态是 `crates/api` 同源生成；现阶段为前端补全数据模块（`web/apps/game/src/editor/apiData.ts`）对绑定层手动同步。
- 编辑代码请求在当前 tick 结束后暂停，保存触发热重载（对齐 [编程与调试体验](../game-design/05-programming-and-debugging.md)）。

## 调试器

- 暂停、恢复、单步、变速。
- 机器人面板：上一 tick 受理通过的动作及其结算结果（`last_result`）；受理失败的码在调用时同步返回，不进该记录。
- 失败原因可视化：目标被占用、电量不足、不相邻、目标已满等在画布与面板上直接标注。
- 日志面板：`Game.log` 输出、受理失败与结算记录、玩家代码错误；只有可靠位置才提供源码跳转。快照合并不删除事件，游标缺口明确提示历史已过期。显示宿主故障最后提交请求，帮助玩家对账。
