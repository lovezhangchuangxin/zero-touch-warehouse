# 风险原型与验收

原则：先验证最难、最不确定的部分；渲染与经营内容都在其后。以下原型按优先级排列，均为一次性验证程序；但原型中产生的测试用例——双语言 API 一致性、失控与中断回归、热重载浸泡、确定性双跑、存档故障注入、白名单逃逸——在原型通过后沉淀为正式回归套件，长期运行于 CI。

## 原型 1：玩家代码运行时（最高优先）

范围：一台机器人、`Game.tick` 最小 API、双语言 `loop()`、全局变量保留、执行超时、热重载。无界面，命令行输出。

通过标准：

1. `while (true) {}` / `while True:` 在预算时间内被中断；世界照常结算已受理动作后暂停；游戏进程无恙。
2. `except` / `finally` 持续吞掉 `KeyboardInterrupt` 的 Python 代码：宽限期后宿主进程被终止，桌面应用不退出；世界照常结算已受理动作并暂停；重启宿主后可继续运行；全程不回档。
3. 不可中断运算（纯 C 死循环、超大操作数的 BigInt）：走宿主终止路径恢复，并记录从超限到终止完成的延迟。
4. 无限增长的数组 / 列表：JS 销毁重建 Runtime 并经救援序列化恢复 `Game.memory`；Python 收到 `MemoryError` 暂停，热重载后配额释放。
5. 自链式微任务（`Promise.resolve().then(f)` 循环）在清空阶段可被预算与中断覆盖。
6. 连续 1000 次热重载浸泡：无内存泄漏、无性能退化（重点观察 Python 命名空间重建路径）。
7. 确定性：同代码同种子双跑一致；对照覆盖"进程重启 + 读档"与"中途热重载"两种情形。
8. 同一组 API 测试用例在 Python 与 JS 下全部通过（同名、同拼写、同结果码）。
9. 白名单外能力被拒：Python `open` / `input` 与白名单外 import 返回可读错误。
10. Game 调用经 IPC 的往返开销量测：单次调用、单 tick 百次调用、万实体规模下的查询往返，确认量级在 tick 预算内。

## 原型 2：Steam 壳

范围：Tauri 空壳 + steamworks adapter，Windows 与 macOS。

通过标准：成就上报、云存档读写、签名公证流程走通；确认 Overlay 实际表现并记录结论。

## 原型 3：渲染与 IPC

范围：50×50 网格、约 200 实体，世界线程以 100 tick/s 快进并推送快照，Pixi 渲染。

通过标准：渲染不掉帧、进程内存平稳（前端消费慢时快照通道合并丢弃，不膨胀）；玩家代码长时间执行期间界面命令仍可点击（command 异步验证）。

## 原型 4：Python 打包

范围：python-build-standalone 随 Tauri 应用打包，Windows 与 macOS 加载并执行白名单标准库代码。

通过标准：两平台冷启动加载成功；macOS 上 lipo 合并的 universal 构建可用；白名单外 import 被拒绝并返回可读错误；附带的许可文本齐备；记录裸解释器内存基线，校准 Python 配额数值。

## 里程碑顺序

```
原型 1–4（并行推进，原型 1 优先）
→ 教学第一关端到端（移动、取放、一箱入库，含编辑器与渲染）
→ 完整经营循环（市场、订单、充电、存档）
→ 多机器人与冲突、教学关卡序列
→ Steam 发布工程（成就、云存档、双平台构建）
```

每个里程碑的玩法验收对照 [首期范围与待定事项](../game-design/07-scope-and-open-questions.md)。
