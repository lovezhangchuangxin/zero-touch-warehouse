# 风险原型与验收

先验证玩家能否写出可解释的仓库程序，同时用最小范围验证双运行时可行性。原型通过必须有测试输出与测量记录，文档里的目标不表示已完成。双语言仍是首期要求，不必等完整生成器和发布工程完成才开始试玩。

## 原型 A：最小运行时与提交契约

分两步交付，让"一个机器人搬一箱货"的闭环（原型 B）尽早开始，而不是先精装完整协议。

- **A0（JS 单语言，最小协议）**：JS loop、Game.tick、移动、接单、受控 memory 最小集（标量 / 列表 / 映射赋值、原子拒绝、原生容器深拷贝陷阱）、请求-回复 IPC、运行时内中断与主进程终止两层看门狗、宿主查询镜像最小版。不实现 host_epoch、请求去重与重复消息机制——它们保护的是值得保护的存档，闭环跑通前没有意义。无完整编辑器，手写最小适配建立共享测试。
- **A1（完整协议与双语言）**：补全 host_epoch / execution_id / request_id、请求去重缓存、执行关闭与旧消息拒绝；接入 Python 宿主与资源限制；memory 值模型测试矩阵全量执行。A1 不晚于第一个对外版本。

验证表中：无限循环 / 吞中断、无限分配、初始化失败、接单与记账间崩溃、memory 原子性、主进程边界在 A0 即以 JS 验收；IPC 故障注入、旧消息与重复消息、memory 全量值模型、热重载浸泡、能力收窄在 A1 验收。

| 验证 | 必须满足 |
| --- | --- |
| 无限循环、吞中断、长运算 | 运行时中断或宽限期后终止宿主，主进程保持响应；记录请求关闭点、终止延迟，已提交状态保留 |
| 无限分配 | 触发资源限制，宿主终止或重建；恢复访问主进程 memory，无救援序列化或旧拷贝回退 |
| 初始化失败 | 包括写 memory 后抛错、入口缺失、宿主崩溃；世界及原 memory 不变，临时分支被丢弃 |
| IPC 故障注入 | 分别在提交前、提交后回复前、回复后断连；提交结果与主进程记录一致，重启不重放调用 |
| 旧消息与重复消息 | 重复请求不重复执行；异负载同号拒绝；旧 epoch / 已关闭执行拒绝；正常完成与强制关闭竞态只结算一次 |
| 接单与记账间崩溃 | 订单成立，尚未提交的任务记录缺失；示例程序查询真实订单后修复，不再次接单 |
| memory 值模型 | 别名深拷贝、循环拒绝、嵌套写入、失效句柄、字符串数字键顺序、整数边界、Position / 普通数组往返，两语言同结果 |
| memory 原子性 | 超限 / 非法修改不改变原树；初始化多次修改整体提交或放弃；读档与重载保持已提交内容 |
| 主进程边界 | 超大消息、查询结果、日志、memory 深度与寻路节点预算受限，取消检查有效；终止按钮不等待 Game 队列 |
| 热重载浸泡 | 1000 次后检查内存趋势与延迟分布，覆盖 Python 模块缓存、受控句柄释放和 JS Runtime 重建；超预算则改用宿主重启验证，不把命名空间重建当作完整清理 |
| 能力收窄 | 白名单外 import、文件打开等返回可读错误；仅验证误用防护，不宣称恶意代码安全 |

测量镜像产出与增量回放的耗时 / 字节、变更型调用与 memory 写的单次往返，以及代表性脚本整 tick 的 p50 / p95 / p99：分别覆盖一台、五台机器人及更大压力场景，记录剩余 IPC 调用数与传输字节。预算参考公式见 [03](03-player-runtime.md)，系数与配额根据结果冻结；快进目标与保护预算分别验收。memory 写占比触发的重议判据见 [06](06-persistence.md)。初始化、宿主重启、超限到停止的延迟也须记录。

## 原型 B：一台到五台机器人的可玩闭环

范围：最小画布、文本代码输入、单步、动作结果面板；固定小地图与订单，完成入库、地面暂存、上架、充电、交付。尽早在同一场景运行两语言等价脚本，不等待市场平衡或完整 Steam 集成。

玩法验收：一台机器人完成闭环；五台机器人时任务分配与交通规划显著改变吞吐；失败可从面板解释；玩家能够修改代码解决至少一类堵塞。记录具体脚本、地图和完成 tick 数。若只能靠反复猜测规则解题，先修动作语义与诊断，不继续堆内容。

模拟回归使用 [玩法 03](../game-design/03-simulation-and-actions.md) 的资源表，并至少覆盖：

- 货架余一格，两机器人反序提交 give，始终小 id 胜；同箱竞争同理。
- 移动链、二元交换、三元以上环、前端受阻、落点争抢失败不递补。
- move 与 drop 争同格、drop 到成功 / 未成功离开的机器人格。
- 被动转交与主动取放争同箱或容量；目标移动成功 / 失败两分支。
- 销毁主体 / 目标、取消车辆后已受理动作失败；不扣电，不复制或遗失货物。
- 每 tick 充电争抢及下一 tick 重新释放；充电与转交同 tick 不预支新增电量。
- 所有成功转移保持每箱唯一归属、容器容量和地图占位不变量；每机器人每 tick 至多一个主动成功动作。
- 固定管理操作影响后，排列机器人提交顺序：五台以内穷举全排列，更多台随机排列；受理集合、结算结果与世界哈希一致。移动与资源求解用小规模穷举和不变量测试，不仅测试教学脚本。

## 原型 C：渲染、诊断与存档

范围：50×50 网格、约 200 实体，目标 100 tick/s；慢前端、暂停管理、单步和运行时故障同测。记录测试机器、系统、构建版本与目标帧率；通过标准需含帧时间分布、快进实际速率、稳定内存上界，不能只写“不掉帧”。

- 人为暂停前端消费后恢复：只显示最新状态；仍在保留窗口内的事件完整按序取得，超窗口返回准确 gap，无无限队列。
- 受理失败、订单完成和宿主终止可从事件定位；日志刷屏不抹去最近故障摘要。
- 存档世界与 memory 来自同一安全点；活动 tick 中存档请求排队，暂停时立即取数。
- 磁盘满、临时写失败、替换前后崩溃、首次创建及连续保存故障注入；旧档有效，旧序号不能覆盖新档。
- 存档覆盖下一实体 id、预留口与下一 tick 到场事件、PRNG、场景进度、已加载代码及独立草稿；读档初始化失败也不破坏存档状态。
- 确定性分三套测试：模拟输入重放；固定初始化时序的双运行；仅持久控制状态且幂等初始化的恢复等价。超限按记录的请求截断点重放，不要求自然墙钟超限完全一致。

## 原型 D：双平台打包风险

最小宿主可运行后即在 Windows / macOS CI 验证，不作为玩法试玩的前置门槛。验证 rquickjs / CPython 构建加载、标准库白名单、许可文本、宿主启动路径以及签名公证；macOS universal 合并按实际发行物依赖清单验证，不预设只涉及单个动态库。失败先解决发行方式，再扩大运行时绑定。

Tauri 空壳接 Steam adapter，记录成就、Cloud、Overlay 实测结论；Steam 发布工程在玩法闭环后完善。平台范围以 [07](07-steam-platforms.md) 为准。

## 里程碑顺序与退出条件

1. 最小动作规则 / IPC / memory 契约与 JS 运行时风险验证（A0），双平台构建冒烟（D）尽早并行。
2. 一台到五台机器人的闭环与调度试玩（B）尽早开始，确认失败可解释、调度有收益；完整协议与 Python 宿主（A1）在首个对外版本前完成，不阻塞 B 的 JS 试玩。
3. 完整市场、订单、借贷与商店；把经济不变量变为属性测试，校准周转与囤货取舍。
4. 编辑器完善、存档与诊断压力验收（C）、教学场景及目标系统，验证重开和转持续经营。
5. Steam 成就 / Cloud、正式双平台签名打包与发布回归（D）。

A–D 是风险与验收分组，不要求先完成所有组再试玩。每个阶段产生的契约、故障注入与不变量测试保留到正式 CI；原型代码只复用已明确归属的模块。若核心语义测试失败，修复规范与实现后再扩展内容。
