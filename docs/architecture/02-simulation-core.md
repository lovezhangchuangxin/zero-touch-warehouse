# 模拟核心与确定性

## 世界线程与 tick 状态机

`World` 由世界线程独占，每个 tick 串行经过固定阶段，语义对齐 [Tick、动作与电力](../game-design/03-simulation-and-actions.md)：

```
1. tick 边界事件    车辆到场、市场刷新
2. 生成 tick 快照   含上一 tick 结算结果（last_result）
3. 调用 loop()     经宿主进程执行：玩家查询快照、提交动作（受理制）、执行管理操作（即时生效）
4. 统一结算        冲突裁决 → 动作执行 → 车辆离场 / 收款 / 释放装卸位
5. 计息、产出渲染快照与日志，tick 序号 +1
```

- 阶段 3 中玩家代码出错或超限时：已受理动作与已生效管理操作照常进入阶段 4，之后世界暂停并报错（见 [03](03-player-runtime.md) 故障分级）。
- 阶段内顺序细则（车辆出现于 `loop()` 之前、离场与收款同结算内完成等）以 [玩法设计 03](../game-design/03-simulation-and-actions.md) 为准。
- 界面命令在世界线程的固定安全点执行：运行中，管理命令（购买、销毁）在下一 tick 边界（阶段 5 之后）生效，玩家在下一份快照中可见；暂停与单步时立即生效。会话命令（暂停、变速、存档）在 tick 完整结束后生效。同一安全点的命令按 FIFO 执行，并记录各自生效的 tick。玩家代码内部发起的管理操作不受此规则约束，仍即时生效。

## 确定性规则

同一平台、同一存档、同一份玩家代码、同一版本，模拟结果必须一致：

| 规则 | 内容 |
| --- | --- |
| 随机源 | 模拟内一切随机使用固定种子的伪随机数生成器（PRNG，xoshiro 家族），种子与状态入存档；具体算法与状态字节布局随存档格式冻结，变更须迁移旧档；禁止系统随机与系统时间 |
| 时间 | 当前 tick 序号是唯一时间概念；市场波动、装卸位分配只依赖 tick 序号与 PRNG |
| 遍历序 | 一切集合遍历按 id 升序（BTreeMap 或显式排序），不依赖哈希表迭代顺序；以 CI 双跑一致性测试兜底（见 [08](08-validation.md)） |
| 数学 | 市场与经济计算只在 `sim` 内用 f64 完成；不调用语言运行时的数学函数，玩家侧不提供会进入模拟的随机或数学入口 |
| Game.memory | 序列化表示保持键的迭代顺序，热重载与读档往返不改变遍历结果 |

- 复现承诺不含超限介入的 tick：墙钟预算本身不是确定量，临界代码可能一次通过一次超限，回归测试对此放宽。
- 跨平台、跨版本不承诺逐字节一致（单机游戏无此需求）。

## 渲染快照

- 每 tick 产出：可见实体状态、本 tick 事件（动作成败、车辆到场/离场、订单与金币变动）。
- 快照为不可变数据；Rust 侧缓冲有上界、始终保留最新，且同一时刻至多一帧在途（上一帧未被消费前不发送新帧），前端消费慢时合并丢弃，不反压模拟。
- 首版 JSON 序列化，量测证明必要时再换二进制格式。

## 变速与暂停

| 模式 | 行为 |
| --- | --- |
| 暂停 | 世界线程不推进 |
| 单步 | 推进一个完整 tick 后回到暂停 |
| 常速 / 快进 | 按目标 tick 频率推进；玩家代码每 tick 全额执行，快进的实际频率受每 tick 实际耗时约束，达不到目标频率时连续推进 |

## 待定

- 常速与快进的默认 tick 频率（参考值：常速 1–10 tick/s、快进 50–200 tick/s，随界面观感与每 tick 实际耗时校准）。
- 渲染快照的事件字段结构（随 [API 设计](../game-design/08-api-design.md) 的 `last_result` 结构一起冻结）。
