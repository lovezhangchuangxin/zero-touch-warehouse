# 存档与恢复

## 权威状态与故障边界

世界状态与 `Game.memory` 均由主进程世界线程独占。宿主只有普通全局变量、只读视图和 memory 访问句柄。宿主故障不撤销主进程已提交的修改；尚未提交的请求和宿主本地计算可能丢失。该保证以主进程仍健康为前提，不包含系统内存耗尽、主进程故障或恶意逃逸。

每条管理请求、每次 memory 修改各自原子提交，但多条 API 调用不是事务。例如接单成功后、写任务记录前崩溃，订单仍成立而记录尚不存在。恢复时程序必须从 `Game.my_orders()`、对象状态与 `last_result` 对账；教程必须演示该模式。不得自动重放不确定的管理调用。

## 状态持久范围（权威定义）

| 状态 | 跨 tick | 跨热重载 / 宿主重启 | 跨存档 |
| --- | --- | --- | --- |
| 普通全局变量 | 保留 | 重置 | 不保存，读档后重新初始化 |
| Game.memory 已提交修改 | 保留 | 保留，重新建立访问句柄 | 保存 |
| 世界状态 | 保留 | 保留 | 保存 |
| 未提交请求 / 本地临时值 | 不作保证 | 丢失 | 不保存 |

## Game.memory：受控数据树

memory 是主进程中的有序数据树，不是宿主原生 dict / Object 的共享引用。Python 提供映射与序列包装器，JS 提供对应代理；支持的操作由 `crates/api` 明确列出并双语言测试，不承诺所有原生容器方法可用。

- 根为映射。映射键只接受字符串；`r.memory` 内部使用 `str(r.id)`，玩家直接访问时也须显式转换。不把整数键自动折叠为字符串，以免 `1` 与 `"1"` 冲突。
- 值允许 null、布尔、有限数字、字符串、列表和字符串键映射。整数范围为 `[-(2^53-1), 2^53-1]`；超范围整数、NaN / Infinity、循环引用、函数、对象实例、JS undefined 与稀疏数组均拒绝。
- Python tuple 和 Position 写入时转为列表；Position 读回就是两个数字的序列，不自动恢复类型。普通 `[3, 4]` 永远不会被猜成坐标类型；坐标接口接受该序列。
- 映射按插入序枚举，覆写已有键不改变顺序，删除后重新插入置于末尾。持久编码使用带类型的节点，映射内容保存为有序键值对序列；不依赖 JSON Object 的数字键枚举规则。两语言绑定必须提供相同的有序枚举。
- 写入原生容器时深拷贝并校验。原生变量后续变化不影响 memory；共享子对象复制为独立子树。读到容器返回受控句柄，嵌套赋值、删除和列表修改同步提交到主进程，标量读取返回值拷贝。
- 句柄通过会话代次与容器节点 id 寻址；祖先被替换或删除时旧句柄失效，访问报 `STALE_MEMORY_REFERENCE`，不会改写后来占据相同路径的新数据。绑定层对容器键查找有槽位缓存（嵌套访问省一次往返）：失效由写入方写透并递归毒化缓存子树、跨代一律回落服务端校验，故该承诺在缓存命中路径同样成立。列表移动元素不改变其容器节点身份；节点 id 不属于存档公开语义，读档后重建。
- 句柄驻留与相等性：同一会话代次内同一节点返回同一包装器实例（JS `===` 成立）；Python 另实现 `__eq__`（按会话代次 + 节点 id 比较），`is` 不作承诺。`Game.memory`、`r.memory` 与逐层访问取得的是同一节点的等价句柄。
- 首期支持映射读取、赋值、删除、成员检查、长度、有序键迭代，以及列表下标读写、长度、迭代、追加、删除指定下标。迭代开始时固定键或元素序列；结构修改不改变本轮枚举。其他操作通过读成普通副本、修改、整值写回完成；显式 `to_dict()` / `to_list()` 返回深拷贝。
- 每次修改在主进程校验后整体提交或整体拒绝，并增加 memory 修订号。字节数、节点数、深度、字符串长度均有上限，IPC 解码前另有限长检查；不得只在存档时检测。失败抛可读错误，原树不变，先前成功的调用仍生效。数值在原型 A 校准。

例如 `items=[]; Game.memory["items"]=items; items.append(1)` 不改变 memory；`Game.memory["items"].append(1)` 才提交持久修改。JS 对应受控列表的 `push`；映射提供 `keys()` 有序枚举，列表提供 `to_list()`、映射提供 `to_dict()`，两语言同名。两种写法的区别进入教程与 API 参考。

同步提交的成本与反转判据：受控树每次修改是一次同步 IPC 往返，换来"宿主崩溃不回退已提交记忆"。原型 A 量测单次写 p95 及代表性脚本每 tick 的 memory 写总耗时；若五机器人脚本中 memory 写占用每 tick 执行预算超过约一成，或单次写 p95 数倍于变更型调用基线（阈值随原型冻结），则重议提交模型——候选为 tick 末批量提交、故障丢弃当 tick 写入；该方案改变故障语义，采纳前必须同步修订 [玩法设计 05](../game-design/05-programming-and-debugging.md) 的对账教学。

`robots` 是保留根键，不能被玩家整体替换或删除；`r.memory` 自动创建相应映射。销毁机器人时清理其记录并使句柄失效。`_move` 由绑定的复合移动实现管理，玩家不得写入。

## 初始化与热重载

初始化禁用世界动作和管理操作，但允许 memory。初始化期间使用主进程中的临时 memory 分支；只有源码执行成功且入口 `loop` 校验通过后才整体提交，失败或宿主退出则丢弃。初始化不会推进 tick。这样初始化失败同时保持世界与原 memory 不变。

热重载在暂停安全点进行，源码与语言切换记录为会话输入。编译或初始化失败后保持暂停，保存编辑器草稿与错误，保留原世界和 memory；恢复前须成功加载有效程序。正常 tick 中的异常不回滚已提交 memory。

## 存档内容与一致性

| 数据 | 说明 |
| --- | --- |
| 世界完整状态 | 实体、订单、预留装卸位、待到场车辆、持续动作、市场与 PRNG 状态、下一实体 id、tick 序号 |
| Game.memory | 同一安全点的数据树与 memory 修订号 |
| 玩家程序 | 已加载的源码、语言；未加载草稿单独保存，不冒充正在运行的代码 |
| 会话与内容 | 场景 id / 版本、教学进度、规则配置及其版本 |
| 版本信息 | 存档格式、模拟规则、API、运行时版本 |

存档只在初始化结束且无活动 tick 的安全点取数；单步执行中收到的请求排到 tick 结束。世界与 memory 由世界线程一起复制为不可变存档数据，再异步写盘，不向宿主请求救援序列化。暂停时可立即取数。

加载不兼容存档明确报错，不静默迁移；读档后重新初始化普通全局变量。初始化的幂等与对账是玩家程序的责任，不承诺任意程序读档后等价于连续运行。

## 写入安全

- 写临时文件并落盘刷新后，用系统级原子替换覆盖目标；平台适用的目录刷新、首次创建和替换已有文件路径分别验证，不使用先删除再改名。
- 写入任务串行，携带存档序号；旧请求不得覆盖新版本。失败保留旧档与明确错误，恢复只选择通过完整性及版本校验的文件。
- 手动存档、自动存档采用同一安全点与写入路径。自动周期与保留数量待校准；断电、磁盘满、写入失败纳入故障注入。

## 恢复行为

| 故障 | 行为 |
| --- | --- |
| 脚本异常 / 可中断超限 | 保留已提交 memory，结算已受理动作，暂停；普通全局变量可能处于部分执行状态 |
| JS 内存超限 / 宿主终止 | 关闭旧代次请求，结算已受理动作，暂停；重建后访问主进程当前 memory，不回退旧拷贝 |
| 初始化失败 | 丢弃初始化 memory 分支，世界与原 memory 不变，保持暂停 |
| 主进程崩溃 | 从最近有效存档恢复世界和 memory，两者一起回退 |
