# 存档与恢复

## 存档内容

| 数据 | 说明 |
| --- | --- |
| 世界完整状态 | 实体、订单、车辆、市场与 PRNG 状态、tick 序号 |
| `Game.memory` | 序列化后的纯数据 |
| 玩家代码文本 | 当前语言与源码 |
| 版本信息 | API 版本、运行时版本 |

加载不兼容存档时明确报错，不做静默迁移；跨版本迁移策略待定。

## 状态持久范围（权威定义）

| 状态 | 跨 tick | 跨热重载 | 跨存档 |
| --- | --- | --- | --- |
| 普通全局变量 | 保留 | 重置 | 不保存，读档后重新执行初始化 |
| `Game.memory` | 保留 | 保留 | 保留 |
| 世界状态 | 保留 | 保留 | 保留 |

## Game.memory 值模型（规范先行）

先定义语言无关的值模型，各语言绑定只把本机类型的子集映射进来，不合规的值在写入或注入时立即拒绝，而不是到序列化边界才发现：

- 允许：null、布尔、整数（±2^53 范围内）、浮点、字符串、列表、字符串键的映射表，以及 Position（编码为 `[x, y]`）。
- 映射表保持插入序；Python 整数键与 JS 整数形式属性键按统一规则编码为字符串键，消除两语言的枚举顺序差异。
- Python tuple 一律映射为列表（往返后是列表）；JS `undefined` 与 `null` 统一为 null；稀疏数组空缺为 null。
- 超出 ±2^53 的整数（Python 大整数）、非有限浮点（NaN / Infinity）、循环引用：写入即拒绝并报错。
- 大小上限在序列化边界检测，超限报错并暂停。

## 序列化时机与救援

- `Game.memory` 运行期常驻执行环境内，只在存档、热重载、故障重建三个边界序列化，不逐 tick 序列化。
- 各边界保留最近一次成功的序列化拷贝；故障重建时的救援序列化允许临时放宽内存配额，失败则回退该拷贝，并明确告知玩家。
- 热重载时序列化失败（如 memory 中存在非纯数据）：阻止本次重载并报错，提供"丢弃 Game.memory 强制重载"选项。

## 写入安全

- 原子替换：写临时文件并落盘刷新（fsync）后，用系统级原子替换（Windows `ReplaceFileW`，macOS 同目录 `rename`），替换后刷新目录；不使用"先删除再改名"的多步序列。
- 异步写串行化：存档任务按提交顺序执行，每次写入携带单调递增序号；旧快照的写入后完成时不得覆盖新序号已写入的存档。
- 自动存档周期待定（参考值：每 1–5 分钟游戏时间或关键事件后）；手动存档随时可用，教学关卡支持重开当前关。

## 崩溃恢复

| 故障 | 恢复行为 |
| --- | --- |
| 脚本级错误（异常、超限、Python `MemoryError`） | 不重建执行环境：结算已受理动作后暂停（见 [03](03-player-runtime.md)） |
| JS 内存超限 / 热重载 | 宿主进程内重建执行环境并注入 `Game.memory` |
| 宿主无响应 / 宿主崩溃 | 主进程终止并重启宿主进程；世界照常结算与暂停，不回档，损失仅普通全局变量 |
| 主进程崩溃 | 从最近自动存档恢复；这是唯一的回档来源，玩家代码故障不落入此行 |
