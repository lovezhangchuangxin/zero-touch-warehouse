# 玩家代码运行时

## 执行模型

- 玩家编写一份完整程序：加载时整体执行一次（初始化），此后每 tick 同步执行一次 `loop()`。
- 玩家代码全部运行在**宿主进程**（runtime host）中：主进程把"执行第 N tick"作为同步请求发给宿主；宿主执行 `loop()`，变更型 `Game` 调用（动作受理、管理操作）与 memory 读写经同步 IPC 回到主进程、由世界线程即时应答，数据查询经宿主本地镜像应答（见「宿主本地查询镜像」）；世界线程在等待 `loop()` 返回期间持续应答宿主请求。
- Player Phase 的世界线程是**消息循环**而非嵌套调用栈：发出执行请求后只处理四类事件——Game 请求应答、执行完成、执行故障、看门狗 / 控制路径超时；禁止世界线程阻塞在"调用宿主并等待"的原语内（与应答义务互锁成死锁）。玩家看到的同步 API 由请求-回复协议与执行定界保证，不依赖线程调用栈嵌套。
- 动作受理与结算都在主进程：宿主被终止时，已受理动作与已生效管理操作完好保存在 World 中，照常结算。
- 同步执行，不向玩家提供任何异步宿主能力（无定时器、网络、动态加载）；只接受源码文本，不接受任何预编译产物。
- 同一存档同一时间只运行一种语言；切换语言重启宿主进程。
- 初始化阶段世界只读：机器人动作与管理操作一律受理失败并返回专用结果码（如 `INIT_PHASE`，命名随 API 设计冻结），仅允许查询、日志与 `Game.memory`。memory 写入在主进程临时分支中，初始化成功才提交，失败丢弃；详见 [06](06-persistence.md)。
- 术语：**执行环境**指承载玩家代码的实例——JS 为 Runtime + Context，Python 为解释器内的玩家命名空间；**热重载**即玩法设计中的"代码重载"。

## 生命周期

| 事件 | 宿主进程 | 执行环境 | 普通全局变量 | Game.memory |
| --- | --- | --- | --- | --- |
| 每 tick 调用 `loop()` | 运行 | 复用 | 保留 | 保留（主进程权威） |
| 脚本级错误（见故障分级） | 运行 | 存活 | 保留 | 保留 |
| 热重载 | 运行 | 重建 | 重置 | 重新建立主进程 memory 句柄 |
| 宿主终止（无响应 / 崩溃）/ 语言切换 | 重启 | 重建 | 丢失 | 访问主进程当前已提交 memory |
| 读档 / 重开 | 运行 | 重建 | 重置 | 从存档恢复 |

- 重建按语言实现不同：JS 销毁并重建 Runtime（耗时须实测）；Python 解释器在宿主进程生命周期内常驻——CPython 不支持可靠的反复初始化与终结，重建的是玩家命名空间（全新模块字典重新执行程序）。
- 全局变量与 `Game.memory` 的持久范围以 [06](06-persistence.md) 为权威。
- 宿主进程内的重建在暂停期间完成，体感目标百毫秒级；宿主进程重启（含解释器初始化）目标数百毫秒级。

## 资源限制（三层）

| 层 | 手段 | 超限行为 |
| --- | --- | --- |
| 运行时内 | JS：堆上限与中断处理器；Python：配额分配器与 `KeyboardInterrupt` 注入 | 优雅失败：脚本级错误，带完整堆栈 |
| 宿主进程 | 宿主内看门狗：deadline 到期注入中断，宽限期内反复注入 | 同上——绝大多数失控止步于此层 |
| 主进程（权威） | 独立看门狗对 tick 请求计时，超宽限期终止宿主进程；世界线程在安全点关闭该代次请求 | 终止重启：结算已受理动作后暂停报"代码无响应"；主进程健康时已提交状态不回退 |

结构性限额：`Game.memory` 大小、日志条数与字节、`find_path` 调用成本（数值待定），在每次修改或调用边界检测并报错；主进程请求解码和结果构造也必须受字节数、节点数和耗时上界约束。

每 tick 执行预算的规则：

- 预算是失控保护阈值，不是节流器：超过即判定失败并中断；未超过时 tick 快慢由变速控制与实际耗时决定。
- 预算与速度模式无关：速度模式不改变预算公式；墙钟调度与系统负载仍可能造成临界代码偶发超限，不承诺跨速度必然同样通过。
- 预算随实体数自动放宽：默认预算 = 基础值 + 每实体余量 × 本 tick 快照中的对象总数（实体数是世界状态的确定性函数）。参考值：基础 20ms、每千实体 10ms、上限 500ms；可在设置中手动覆盖。
- 程序初始化有单独预算。
- `loop()` 返回后清空微任务队列，清空过程计入同一预算与中断覆盖。

限制的目标是防止失控拖垮游戏进程，不是防恶意攻击——主进程健康时，宿主失控不会回滚已提交世界与 memory；未提交调用、本地计算与普通全局变量可能丢失，跨调用的一致性由玩家恢复对账处理。进程隔离同样不是安全边界：能力面收窄可防误用，防不了蓄意逃逸。首期定位为运行玩家自己编写的代码；任何引入他人代码的功能（创意工坊、代码分享）上线前必须先建立真正的安全边界，在此之前不宣称可安全运行不受信任的代码。

## JS 宿主（rquickjs / quickjs-ng，宿主进程内）

- 版本随构建锁定。
- Runtime 启动时设置：堆内存上限（不启用自定义分配器 feature，否则上限失效）、栈上限、中断处理器（deadline 到期返回 true，引擎抛出不可捕获异常终止执行，玩家代码无法捕获绕过）。
- 玩家代码整脚本求值，不注册模块加载器；动态 `import()` 运行时报错，没有加载能力。
- 中断依赖引擎在检查点轮询；个别单条长运算（如超大操作数的 BigInt 运算）存在检查间隔较大的窗口，由主进程终止层兜底。
- Runtime 非线程安全：宿主内看门狗只注入中断，销毁与重建由宿主自己的执行线程完成。
- 内存超限后的 Runtime 状态不可信：销毁重建；重建后重新建立主进程 memory 句柄，不从故障运行时提取持久数据。

## Python 宿主（PyO3 / CPython，宿主进程内）

- python-build-standalone 发行物，版本随构建锁定。
- 解释器驻留宿主进程的调用线程，且该线程即解释器主线程——CPython 的中断信号只在解释器主线程生效，这是中断能落在玩家代码上的前提。
- 执行时间：宿主内看门狗线程调用 `PyErr_SetInterruptEx` 注入 `KeyboardInterrupt`（字节码边界生效），宽限期内反复注入；不使用 `PyThreadState_SetAsyncExc`（不安全）。
- 内存：在解释器初始化前安装覆盖 RAW、MEM、OBJ 三个分配域的配额分配器（覆盖 OBJ 域即放弃 pymalloc，分配变慢但配额覆盖全部对象分配），超额分配返回失败、玩家代码收到 `MemoryError`；配额覆盖解释器自身、标准库缓存与绑定对象的全部占用，数值按裸解释器基线校准（原型 D 实测）。
- 能力面：`__builtins__` 替换为白名单（移除 `open`、`input`、`breakpoint` 等）+ `sys.meta_path` 白名单 finder + audit hook 拦截 import、动态加载与文件打开等事件；标准库只放行纯计算模块（如 `math`、`collections`、`heapq`，清单待定），不提供 pip 与 site-packages。
- 已知边界：纯 C 循环（如对无限迭代器求 `max`）不经过字节码边界，中断无效；白名单选型须避开此类入口，残余风险由主进程终止层兜底。

## 双语言成本账与重议触发器

双语言是已定产品方向，其技术成本集中在 Python 侧，此处显式记账，避免"已定"掩盖累积成本：配额分配器替换三域即放弃 pymalloc；`__builtins__` / meta_path / 标准库白名单是持续维护项且须避开不可中断的纯 C 入口；CPython 不可靠重初始化使热重载只能重建命名空间（是否泄漏由浸泡测试验证）；macOS universal 需 lipo 合并发行物并逐一签名内嵌动态库，是打包风险最大的一块。

出现以下任一情况时，显式评审"JS 先行、Python 后置"的范围收缩，而不是默认坚持：原型 D 的 universal 合并与签名公证无法在一个里程碑内收敛；原型 A 浸泡显示命名空间重建泄漏，改用宿主重启后热重载延迟显著超标；Python 侧资源限制与故障分级的实现复杂度挤占玩法开发、连续拖期两个里程碑。评审结论与理由记录进本目录文档。

## 故障分级

| 级别 | 触发 | 处理 |
| --- | --- | --- |
| 脚本级错误 | 语法错误、未捕获异常、执行超限（运行时内中断生效）、Python `MemoryError` | 中断或捕获 → 结算已受理动作与管理操作 → tick 边界暂停 → 展示错误类型、源码位置与堆栈。执行环境与全局变量保留，修改代码热重载后恢复 |
| 环境级故障 | JS 内存超限；主动热重载 | 宿主进程内销毁重建执行环境；重新建立主进程 memory 句柄；主动重载失败保持暂停 |
| 宿主终止 | 中断被玩家代码持续捕获吞掉或陷入不可中断运算，超过宽限期；宿主进程自身崩溃 | 主进程终止宿主 → 结算已受理动作与管理操作 → 重启宿主并重新建立 memory 句柄 → 暂停并报"代码无响应"或"宿主崩溃"。主进程健康时已提交世界与 memory 不回退，未提交调用与普通全局变量可能丢失 |

- 宿主故障且主进程健康时不回滚已提交状态；主进程自身崩溃时按有效存档粒度恢复（见 [06](06-persistence.md)）。
- 界面不依赖世界线程与宿主进程：webview 与 Tauri 主线程保持响应（见 [05](05-frontend.md)），宿主故障时"终止并恢复"通过独立控制路径保持可操作；主进程故障不在此承诺内。
- 三个级别都遵循已提交状态保留规则：已受理动作与已生效管理操作照常结算（对齐 [玩法设计 03](../game-design/03-simulation-and-actions.md)）——受理记录与结算都在主进程，宿主终止不影响履约。
- "宿主终止"的报错须给出可行动的原因提示（如"你的代码可能在循环中捕获了所有异常"），附最后已提交 API、tick 和请求编号；只有取得可信堆栈时才标注源码位置，不把最后 API 位置冒充卡死位置。
- 初始化失败时 `loop()` 未被调用，世界与原 memory 不变。

## IPC 请求与提交协议

- 消息头包含协议版本、宿主代次 `host_epoch`、执行编号 `execution_id`（区分初始化与 loop）、tick、单调递增 `request_id`、类型及负载长度。主进程发起一次执行，宿主串行发出 Game 请求，收到回复后才发下一条；执行完成消息引用最后请求号。
- 世界线程按 FIFO 处理有效请求。每条修改先校验、再原子提交并记录结果，最后回复；该提交点决定是否生效，不以宿主是否收到回复为准。完成消息须等此前请求处理完才允许结算。
- 在当前执行内保存请求结果：重复请求号与同负载返回原结果，不重复扣款或修改；同号不同负载视为协议故障。执行关闭后拒绝全部旧消息，不跨执行自动重试修改。结果缓存受每执行请求数上限约束，达到上限暂停报错。
- 超时 / 断连通过控制路径关闭执行。世界线程在当前单条原子请求完成后的安全点设置关闭标志，尚未开始的排队请求全部拒绝；记录最后提交号，再结算已受理动作。重启增加 host_epoch，旧代次消息永远拒绝。
- 故障可能发生在提交后、回复前：该修改保留。界面展示最后提交号及操作摘要；恢复程序通过世界与 memory 对账，不自动重放该调用。不得声称多条调用具有事务性。
- 看门狗和终止按钮不排在 Game 请求队列后，直接控制宿主生命周期并通知世界线程关闭执行。世界线程不执行无界工作：寻路有节点预算与取消检查点，解码前限制消息长度，查询和日志限制返回大小；杀宿主不等于能打断主进程内部的长运算。
- IPC 错误、版本不符、超大消息与非法对象引用均在主进程校验，不能仅信任语言绑定。协议是资源与一致性边界，不宣称抵御恶意宿主。
- 首版使用有长度前缀的 JSON 消息；编码中的有序映射使用 [06](06-persistence.md) 数据节点表示。数据查询经宿主本地镜像应答（见下节），IPC 量测聚焦镜像产出与增量回放成本、变更型调用与 memory 写的 p50 / p95 / p99；查询批量接口仅作镜像方案不达标时的回退，不能靠延迟提交修改换取性能而悄悄改变故障语义。

## 宿主本地查询镜像

数据查询不走 IPC：tick 阶段 2 由世界线程产出宿主查询镜像（世界查询视图、tick、世界修订号），宿主在本地应答对象、市场、订单、地图类查询；初始化执行前同样以当前世界产出镜像。镜像内容是世界状态的纯函数，不引入新的非确定来源。

- 变更型调用（动作受理、管理操作）与 `Game.memory` 读写仍为同步 IPC。管理操作的响应携带镜像同步增量，宿主按同一 FIFO 回放，保证"管理操作当 tick 可见"与主进程一致；增量回放失败即整体失效重建镜像，不猜测。
- `find_path` 与 `Game.log` 走 IPC：计算与配额在主进程，不进镜像。
- 镜像只是读缓存：受理与结算始终以主进程 World 为权威；修订号不一致时查询回退 IPC 并重建镜像。
- 该决策取代"先量测再决定查询缓存"的延期路径。若原型 A 量测显示镜像产出与回放成本使快进目标不可达，按"镜像瘦身 → 批量查询接口 → 恢复逐查询 IPC"的顺序回退，每步重测后再进。

## 待定

- IPC 传输实现与镜像承载方式（序列化缓冲或共享内存）；宿主进程冷启动耗时目标；宽限期数值。
- 执行预算公式的系数与上限数值（参考值见上文，随原型 A 实测校准）。
- JS 堆上限与 Python 配额数值（参考值：256MB / 512MB 量级）。
- Python `__builtins__` 与标准库白名单最终清单；`random` 是否以独立派生流提供（不得读写模拟 PRNG 状态）。
- `Game.memory` 大小上限、日志限额、`find_path` 成本模型（与 [API 设计待定项](../game-design/08-api-design.md) 合并跟踪）。
