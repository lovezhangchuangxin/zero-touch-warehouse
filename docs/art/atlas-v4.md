# 墙体改瓦片图集（2026-09-13 决策，已生成并接入）

逐件生成墙的方式有方法论缺陷：墙是**连续建筑**而非独立物件，每件单独作画必然带来色差、锥形收边、面板错位——提示词只能缓解。改为**瓦片图集**方案，已落地：

- **生成**：一次生成"完整房间边界"（四条连续墙带 + 四角一体作画，室内外全空），成品 `atlas-walls-tileset.png` 验收合格。
- **切片**（`tools/slice_walls_tileset.py`，在 `slice_atlas_v4.py` 之后运行）：**均匀网格切块法**——保留最大连通域（丢弃游离色斑）→ 按带厚归一并取整到整数网格（本批 7×7）→ 整环切成 7×7 个 256×256 瓦片，边界瓦片即墙瓦：**wall_tile_n/s/w/e 各 5 块 + wall_corner 四角**，共 24 块。所有瓦片都是同一幅连续画作的相邻裁块，**拼接无缝由构造保证**；贴边对齐 baked-in（N 瓦带在顶、S 在底、W 在左、E 在右）。
- **摆放**：全部瓦片格子居中直铺即可，无需任何偏移——对齐已烘进瓦片；**门洞 = 该格不铺瓦**，无需专门素材。
- **清理**：C 表 v2 的 14 个旧墙件精灵已从包内移除（manifest 记录于 `superseded`）；**立柱、排水格栅保留**（独立物件）；A/B/D 不受影响。
- 现有精灵总数 **69**；场景验证（`tools/scene_test.py` → `atlas-v4-scene-test.png`）：瓦片铺墙四边连续无缝贴边、门洞留空演示、其余物件不变。

**切片方法定稿（连通域提取 + 足迹画布）**：

- **连通域提取**：整图 8 连通标记 alpha 连通块，按"包围盒与槽位相交 + 质心落在槽位邻域"归属槽位。大于槽位的物体（长卡车等）完整保留不裁剪；小于 100px 杂散斑自动丢弃（尘土/压毁箱白名单）。
- **画布 = 逻辑足迹**：1×1 = 256×256，1×2v = 256×512，2×1h = 512×256，标记 256×256，图标/特效 192×192。内容等比缩放到恰好放入并居中，锚点 = 画布中心 = 格子中心。
- **竖墙按高度归一**（grounded1h 类）：南北向墙以高度 = 1 格归一，厚度成为约 0.48 格窄条，与概念图左右墙一致；横墙按宽度归一（长 = 1 格）。墙图案横跨画布全长，同向相邻摆放无缝拼接。
- **墙件特例处理**（区别于其他居中物体）：
  - 切片端：可平铺墙件在拼接轴两端各裁 5% 锥形收边再拉伸回画布宽（模型给切口画了圆角收头，对接即出缝），切口变为满高平直切断；
  - 摆放端：墙**贴格子边缘**对齐而非居中——北墙贴上缘、南墙贴下缘、西墙贴左缘、东墙贴右缘（贴哪条边取决于墙在房间哪一侧），相邻件叠约 1px 掩盖色差；manifest 的 `placement` 字段记录每件墙的贴边提示。
- 立柱、墙角等强透视物件等比缩小放入足迹画布，宽度略窄于一格（0.68–0.93），引擎可按需微调。
- 产出 **59 个精灵**；场景验证（`tools/scene_test.py` → `atlas-v4-scene-test.png`）：四面墙贴边连续无缝、卡车纵跨两格对位装卸位、货架叠箱、地面箱占满整格、其余物件居中于所在格。

# 完整场景素材图集 v4（v1 记录存档）

按 v3 的验证结果修复推进：风格头沿用 v3 成功骨架，修正已知失败项。三处策略变化：

1. **透明背景**：直接要求真 RGBA 透明（ChatGPT 生图支持），不再画棋盘格。验收时用脚本校验 alpha 通道；若批次仍输出 RGB+假棋盘格，退回纯色底抠图预案。
2. **货架单层化**：游戏货架为单层（一格最多四箱、单层摆放），只生成一个空货架底座，0–4 箱状态由引擎在固定槽位叠放箱子精灵。卡车同理只画空车，车斗货物用箱子精灵叠放（订单数量 2–16 浮动，预烘焙满车必然穿帮）。
3. **动画走"基座 + 补间 + 特效叠加"**：机器人不画动作帧。移动流畅性由渲染插值承担（逻辑格位置与渲染位置分离，tick 内 lerp 滑动）；取放货物用箱子抛物线补间 + 尘土/闪光特效；充电用闪电图标 + 充电桩工作态；失败用抖动 + 红色感叹号；低电量用悬浮电池图标。机器人表因此缩为空载/眨眼/载货参考各四向。
