# 经营、商店与成长

## 初始资源

已确定玩家初始拥有一定金币、一台机器人和一个充电桩。具体金币、电池初始状态和地图大小待定。

初始装卸口或购买装卸口的启动资金必须补齐：当前尚未确定初始直接赠送装卸口，还是通过教学购买。无论选择哪种，都应保证玩家能完成第一份合同。

## 金币循环

当前基线采用客户货物代管模式，通过完成物流合同获得服务费。金币主要用于购买机器人、充电桩、货架和装卸口。

新增机器人提高并行搬运能力，但也带来交通和充电压力；新增货架增加存储能力，但占用地面；新增装卸口缓解车辆排队，同时需要机器人供给能力匹配。

定价、报酬和延误损失需要共同平衡，避免单一设备成为没有取舍的最优投资。

## 商店与建造

已确定支持购买机器人及建筑，游戏对象支持 `destroy`。

当前基线：

- 界面和代码均可进行管理操作。
- 购买后放置到合法空格。
- 购买、放置和销毁的资金与占位校验必须可查询失败原因。
- 购买即时扣费、即时建成生效；同一 tick 内的管理操作按调用顺序结算。管理操作的完整语义见 [API 设计](08-api-design.md)。

## 销毁

当前基线限制：

| 对象 | 销毁前提 |
| --- | --- |
| 机器人 | 必须空载 |
| 货架 | 所有货物清空 |
| 装卸口 | 没有靠泊车辆 |
| 充电桩 | 可销毁；已受理的充电动作在结算时失败并返回原因 |

销毁退还部分金币，比例待定。常规销毁不连带删除客户货物。货物本身是否允许主动销毁、如何赔偿仍待决定。

## 教学与主线

已确定持续经营为主，教学关卡引导入门。建议按依赖关系逐步教授：

1. 查询位置，单步移动机器人。
2. 从车辆取货、存入货架，再装车交付。
3. 电量检查与充电。
4. `loop()`、全局状态与动作结果处理。
5. 查询订单并逐单接受。
6. 多机器人任务分配、拥堵处理。
7. 商店扩建与自动筛选合同。

以上为教学内容顺序建议，不规定关卡数量、解锁门槛或是否强制完成教程。

## 试错与恢复

支持暂停、单步、存档和重开，让玩家敢于修改代码。前期延误主要损失奖励与吞吐量，避免一次错误直接结束经营。

后续必须明确合同失败后的货物清退、负金币处理，以及设备不足时恢复经营的途径。不能依赖出售最后一台机器人等隐式补救机制保证游戏可继续。
