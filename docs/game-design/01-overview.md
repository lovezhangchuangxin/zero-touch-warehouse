# 游戏定位与核心循环

## 已确定方向

《无人仓库》是一款单机 2D 编程游戏。玩家拥有全局视角，通过 Python 或 JavaScript 程序管理一座仓库，控制机器人搬运、存储和交付货物。

主线以持续经营为主，通过教学关卡引导入门。玩家初始拥有一些金币、一台机器人和一个充电桩，逐步购买设备、扩大处理能力。

## 核心体验

玩家先让仓库自动运转，再观察缺货、堵塞、订单延误和设备闲置，通过修改程序与仓库布局提高吞吐量。主要作品是一套不断完善的仓库管理程序。

核心循环：

1. 查询并选择物流合同。
2. 入库车辆到达，机器人卸货。
3. 货物分类并暂存于货架或地面。
4. 出库车辆到达，机器人检索、搬运并装车。
5. 完成合同，获得物流服务费。
6. 购买设备、调整布局、优化代码，处理更多并行合同。

## 仓储存在的意义

入库与出库在时间上错开，不同合同的数量、种类和时间安排也不同。玩家需要为等待出库的货物分配空间，并协调多个合同。

偶尔直接从入库车转运至出库车可以是有效策略，但正常合同应当存在暂存需求。第一版每份合同可只包含一入一出两辆车，通过合同之间交错形成调度问题。

## 成长路径

| 阶段 | 玩家解决的问题 |
| --- | --- |
| 首次自动化 | 一台机器人完成取货、移动、存储和交付 |
| 稳定运行 | 跟踪合同状态、按需充电、处理动作失败 |
| 多机器人协作 | 建立任务队列，避免重复搬运和交通冲突 |
| 仓库扩容 | 规划货架布局、充电区、通道和多个装卸口 |
| 自动经营 | 预测空间与到车高峰，自动筛选合适的合同 |

首期重点验证从一台机器人发展到约五台的过程是否自然产生上述问题；该数量是体验验证目标，不是机器人数量上限。

## 设计原则

- 规则确定、状态可查询、失败可解释，让程序行为能够被推理。
- 经营压力推动优化，但允许暂停、调试和恢复。
- 物流效率是主要收益来源，首期不引入货物买卖投机。
- 先验证多机器人搬运与调度，再扩展其他物流设备和小游戏。
