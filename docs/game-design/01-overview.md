# 游戏定位与核心循环

## 已确定方向

《无人仓库》是一款单机 2D 编程游戏。玩家拥有全局视角，通过 Python 或 JavaScript 程序管理一座仓库，控制机器人搬运、存储和交付货物。

主线以持续经营为主，通过教学关卡引导入门。玩家初始拥有一些金币、一台机器人、一个充电桩和一个装卸位，逐步购买设备、扩大处理能力。

## 核心体验

玩家先让仓库自动运转，再观察市场价差、库存积压、堵塞和设备闲置，通过修改程序与仓库布局提高资金周转和吞吐量。主要作品是一套不断完善的仓库经营程序。

核心循环：

1. 查看市场，买入价格合适的卖单。
2. 车辆出现在装卸位，机器人卸货。
3. 货物暂存在地面或货架，等待价格合适的买单。
4. 接下买单，机器人检索、搬运并装车。
5. 车辆装满离场，收取货款，赚取差价。
6. 购买设备、调整布局、优化代码，提高周转与吞吐。

## 仓储存在的意义

收益来自买卖差价：低价买入的货物需要空间存放，等待高价卖出。仓容限制囤货规模，库存占仓即资金被占用，仓库布局与容量直接决定经营上限。

偶尔可从买入车直接倒手至卖出车（直通转运），但正常经营应当存在暂存需求；价差结构使囤货与快进快出各有取舍。

## 成长路径

| 阶段 | 玩家解决的问题 |
| --- | --- |
| 首次自动化 | 一台机器人完成接单、卸货、存储和装车 |
| 稳定运行 | 跟踪订单与库存、按需充电、处理动作失败 |
| 多机器人协作 | 建立任务队列，避免重复搬运和交通冲突 |
| 仓库扩容 | 规划货架布局、充电区、通道和多个装卸位 |
| 自动经营 | 监控市场价差与库存，自动决定买入、卖出与囤货 |

首期重点验证从一台机器人发展到约五台的过程是否自然产生上述问题；该数量是体验验证目标，不是机器人数量上限。

## 设计原则

- 规则确定、状态可查询、失败可解释，让程序行为能够被推理。
- 经营压力推动优化，但允许暂停、调试和恢复。
- 买卖差价与物流效率共同构成主要收益；装卸位占用与资金占用即经营压力。
- 先验证多机器人搬运与调度，再扩展其他物流设备和小游戏。
