# 首期范围与待定事项

## 首期设计基线

- 单机 2D 网格仓库，全局视角。
- 固定大小仓库，先通过增加设备扩容；地图扩展暂不纳入基线。
- Python / JavaScript 同步程序，初始化后每 tick 调用 `loop()`。
- 单箱载重机器人，移动、取货、送货、放下、拾起、充电。
- 多货位货架（基线每货架四箱）、充电桩、通用装卸口。
- 少量货物类型，箱子统一占用一个货位。
- 订单市场、自主接单、完整仓储合同；每合同一辆入库车、一辆出库车。
- 商店购买、受约束的销毁与部分退款。
- 持续经营、教学引导、暂停、单步、变速、存档和动作诊断。

## 首期不考虑

- 迷宫等额外小游戏：用户明确留待后续。
- 传送带、维修、员工、复杂商品价格：当前建议暂缓。
- 电池老化、浮动电价、货物重量体积差异、保质期和品质。
- 随机车辆故障、临时修改客户需求、一批入库多次出库。

## 实施前优先确定

| 主题 | 未决问题 | 影响 |
| --- | --- | --- |
| 初始经营 | 地图尺寸、初始金币、装卸口赠送还是购买 | 第一份合同能否启动 |
| 装卸口 | 占地尺寸、边界限制、交互面 | 地图与寻路 |
| 结算顺序 | 车辆、管理操作、机器人动作、截止判定的顺序；截止 tick 是否包含当 tick | 程序可预测性 |
| 交互冲突 | 多机器人争抢货物或货位、转交与其他动作同时发生 | 数据一致性 |
| 充电冲突 | 多机器人同时请求同一个充电桩 | 调度策略 |
| 合同异常 | 部分装卸、未卸完时出库车到达、超期车辆离场 | 完整状态机 |
| 违约恢复 | 扣款、失败赔偿、货物回收、负金币与经营恢复 | 试错成本与软锁 |
| 程序异常 | 错误或超限时已提交指令如何处理 | 调试与原子结算 |
| 销毁范围 | 货物能否主动销毁、建筑销毁与当 tick 动作冲突 | 客户资产与世界一致性 |

## 随原型继续确定

- 电池容量、充电速率、动作耗电、设备价格、每货架货位数、销毁退款比例。
- 合同发布频率、候选数量、货量、时间分布、报价公式和基础接单门槛。
- 是否提供内置自动接单开关；代码控制靠泊与队列优先级是否进入首期。
- 教学关卡数量、解锁顺序、教学到持续经营的衔接。
- 管理操作是否即时完成，以及占位和资金竞争规则。
- 最终 API、动作结果格式、路径查询语义、持久化数据格式和沙箱限制。

## 原型验证目标

1. 一台机器人可以完成接单、卸货、存储、充电和交付的闭环。
2. 增加到约五台机器人时，任务分配和交通调度能显著影响效率。
3. 货架每格容纳多箱，相对地面暂存节省空间，地面暂存有通道占用代价。
4. 入出库错峰与多个合同重叠，使仓储和选择接单有实际意义。
5. 单步执行和错误信息能让玩家解释机器人为什么没有按预期行动。
6. 合同失败后，玩家仍有明确的恢复经营途径。

这些目标用于评估玩法，不等同于已经通过的测试。
