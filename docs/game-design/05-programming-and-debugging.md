# 编程与调试体验

## 已确定方向

玩家使用 Python 或 JavaScript 编写一个多文件程序控制整个世界。程序在游戏沙箱内同步执行。

一个程序 = 一组玩家文件 + 一个入口（默认 `main.js` / `main.py`）。JS 侧入口是 ESM 模块，其余文件经 `import`（仅相对说明符）引用，入口须导出 `loop` 函数；Python 侧入口整段执行，其余文件以去扩展名的文件名被 `import`（如 `lib.py` → `import lib`），入口内定义 `def loop():`。

代码加载时先完整执行入口（含模块图），之后每 tick 调用一次玩家暴露的 `loop()`。玩家可查询全局信息、控制全部机器人，并执行经营管理操作。

## 执行生命周期

当前基线：

- 普通全局变量在 tick 之间保留。
- 代码重载保留世界状态，但重新初始化程序和普通全局变量。
- 跨代码重载的数据保存在 `Game.memory`，见 [API 设计](08-api-design.md)。
- 编辑代码时请求在当前 tick 结束后暂停世界；恢复运行后才继续推进逻辑时间。
- Python 和 JavaScript 使用相同世界规则与对应 API。

`Game.memory` 是主进程持有的受控数据树，语义见 [API 设计](08-api-design.md) 和[存档与恢复](../architecture/06-persistence.md)。初始化只允许查询、日志与临时 memory 修改；成功后提交 memory，失败保持世界和原 memory。切换语言重建宿主，普通全局变量重置。

## API 能力边界

| 类别 | 能力 |
| --- | --- |
| 查询 | 地图、机器人位置、电量、携带物、货架库存、地面货物、市场挂单与已接订单 |
| 行动 | 移动、取货、送货、放下、拾起、充电 |
| 管理 | 接单与取消、购买机器人和建筑、销毁对象与货物、借贷 |
| 辅助 | 基础路径查询、日志、机器人上一 tick 的动作与结算结果 |

提供 `find_path` 路径查询和 `move_to` 复合移动，帮助新手开始搬运；玩家仍负责选目标、分配任务和解决拥堵，也可编写自己的寻路逻辑。路径查询只考虑静态障碍（见 [API 设计](08-api-design.md)），调用成本限制待定。

查询返回当前 tick 的状态。动作接口调用时立即返回受理结果码（`"OK"` 或失败原因），但不立即改变可查询状态；最终执行结果由 tick 结束的统一结算决定，下一 tick 才能查询。即时生效的管理操作是唯一例外，见 [API 设计](08-api-design.md)。具体行为见 [Tick、动作与电力](03-simulation-and-actions.md)。

## 调试体验

- 暂停、恢复、单 tick 前进和运行变速。
- 查看机器人上一个 tick 的动作受理与结算结果。
- 清晰显示目标被占用、电量不足、不相邻、目标已满等失败原因。
- 提供日志和错误位置，便于定位代码问题。
- 支持手动存档和重开当前教学关卡；持续经营的读档用于恢复与试验。

tick 是游戏逻辑时间。玩家暂停思考或编辑时，市场与车辆不推进，现实等待时间不消耗游戏时间。

## 沙箱约束

代码执行超限时暂停世界并展示错误，避免失控程序让经营状态继续恶化。异常、超限与初始化失败的统一事务规则见 [Tick、动作与电力](03-simulation-and-actions.md)：已受理的命令照常结算后再暂停，初始化失败则世界原样不动。

异步边界：玩家代码只在单次执行帧内运行。JS 的 async/await 语法允许，但微任务只在执行尾部统一清空（计入同一预算与中断），挂起的续体也只能在未来帧内由玩家代码显式恢复——不存在任何帧外执行，也不可能把操作延迟到结算之后。顶层 `await` 等待本执行内不解析的值、未处理的 Promise 拒绝都以可读错误终止；Python 的 `async def loop` 入口直接拒绝。

执行预算、可用标准库、文件与网络访问边界、语言运行时、存档兼容性属于后续技术设计；当前不选定技术栈。

## 故障恢复教学

API 每次调用独立提交；接单与写任务记录之间故障会留下已接订单，不能假定两者一起完成。教程提供从实际订单、机器人携带物和上一动作结果重建任务表的示例。宿主故障保留主进程已提交的 memory，重载仍会重置普通全局变量；任意程序读档后不保证与连续运行轨迹相同。
