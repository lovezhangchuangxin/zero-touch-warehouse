# 编程与调试体验

## 已确定方向

玩家使用 Python 或 JavaScript 编写一份控制整个世界的程序。程序在游戏沙箱内同步执行，不支持异步。

代码加载时先执行完整程序，之后每 tick 调用一次玩家暴露的 `loop()`。玩家可查询全局信息、控制全部机器人，并执行经营管理操作。

## 执行生命周期

当前基线：

- 普通全局变量在 tick 之间保留。
- 代码重载保留世界状态，但重新初始化程序和普通全局变量。
- 跨代码重载的数据保存在 `Game.memory`，见 [API 设计](08-api-design.md)。
- 编辑代码时暂停世界；恢复运行后才继续推进逻辑时间。
- Python 和 JavaScript 使用相同世界规则与对应 API。

`Game.memory` 的数据类型、存档序列化、两种语言切换以及初始化阶段是否允许提交动作仍待接口设计。

## API 能力边界

| 类别 | 能力 |
| --- | --- |
| 查询 | 地图、机器人位置、电量、携带物、货架库存、地面货物、订单和已知到车安排 |
| 行动 | 移动、取货、送货、放下、拾起、充电 |
| 管理 | 接受合同、购买机器人和建筑、销毁对象 |
| 辅助 | 基础路径查询、日志、机器人上一 tick 的动作与结算结果 |

提供基础路径查询，帮助新手开始搬运；玩家仍负责选目标、分配任务和解决拥堵。允许玩家编写自己的寻路逻辑。路径查询是否考虑动态障碍及其成本限制待定。

查询返回当前 tick 的状态。动作接口调用时立即返回受理错误码（`"OK"` 或失败原因），但不立即改变可查询状态；最终执行结果由 tick 结束的统一结算决定，下一 tick 才能查询。即时生效的管理操作是唯一例外，见 [API 设计](08-api-design.md)。具体行为见 [Tick、动作与电力](03-simulation-and-actions.md)。

## 调试体验

- 暂停、恢复、单 tick 前进和运行变速。
- 查看机器人上一个 tick 的动作受理与结算结果。
- 清晰显示目标被占用、电量不足、不相邻、目标已满等失败原因。
- 提供日志和错误位置，便于定位代码问题。
- 支持手动存档和重开当前教学任务；持续经营的读档用于恢复与试验。

tick 是游戏逻辑时间。玩家暂停思考或编辑时，订单不继续倒计时。现实等待时间不应直接消耗履约时间。

## 沙箱约束

代码执行超限时暂停世界并展示错误，避免失控程序让经营状态继续恶化。普通异常、超限、初始化失败时如何处理本 tick 已提交的命令，需要制定统一事务规则。

执行预算、可用标准库、文件与网络访问边界、语言运行时、存档兼容性属于后续技术设计；当前不选定技术栈。
