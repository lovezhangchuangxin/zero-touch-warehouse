# Tick、动作与电力

## 世界结算

已确定以 tick 度量游戏时间，玩家代码同步执行，不支持异步。

当前基线采用“查询状态 → 提交指令 → 统一结算”，动作反馈分受理和结算两层：

1. `loop()` 查询 tick 开始时的世界快照。
2. 玩家为机器人提交本 tick 的动作，每个动作接口立即返回受理结果。
3. `loop()` 正常结束后，系统对全部已受理意图统一校验并结算。
4. 下一 tick 可查询新状态及上一 tick 的结算结果。

调用移动接口后立即读取位置，仍然得到本 tick 开始时的位置。受理通过也不代表最终执行成功，结果以结算为准。

车辆到达、管理操作、机器人动作和订单截止判定之间的精确结算顺序仍待制定。

## 动作受理与错误码

每个动作接口在调用时同步返回一个字符串错误码：

- `"OK"`：意图通过受理检查，进入本 tick 的统一结算。
- 其他取值：受理失败，字符串字面表达原因，例如 `"NOT_ADJACENT"`（目标不相邻）、`"ALREADY_ACTED"`（本 tick 已有受理通过的动作）、`"CARRYING_ITEM"`（取货时自身非空载）、`"SHELF_FULL"`（目标货架无空货位）。最终错误码清单随 API 设计确定。

受理规则：

- 受理检查基于 tick 开始快照和本 tick 已受理的意图，只判定调用时可知的静态条件，如相邻、空载、容量、电量；不预判只能由同时结算产生的结果，如目标格争抢、移动链受阻、充电桩被同 tick 其他充电动作占用。
- 受理失败不消耗行动机会，玩家代码可在同一 tick 改提其他动作。
- 受理通过即占用本 tick 行动机会，此后对该机器人重复提交动作返回受理错误，不静默覆盖。
- 受理反馈可能受同一 tick 内调用先后影响，例如后提交者会立即被告知货架已满；但结算结果不依赖调用顺序。

结算结果查询：

- 每个机器人提供上一 tick 结果查询，返回其受理通过的动作与结算错误码；成功为 `"OK"`，失败原因与受理错误码共用同一词表，如 `"CELL_CONTESTED"`（目标格争抢）、`"BLOCKED"`（移动链受阻）、`"CHARGER_BUSY"`（充电桩被同 tick 充电动作占用）。
- 每机器人每 tick 至多一个受理通过的动作，单个结果槽即可表达；该 tick 未受理通过任何动作时无结算记录。受理失败的错误码调用时已同步返回，不进入该记录。
- 具体方法命名与返回结构随 API 设计确定。

玩家代码抛出异常或执行超限时，已受理通过的动作如何处理，仍属于待定的异常事务规则。

## 机器人动作

| 动作 | 目标与条件 | 电力 |
| --- | --- | --- |
| 移动 | 沿上下左右移动一格，满足占位和冲突规则 | 不消耗 |
| 充电 | 相邻充电桩可提供服务 | 恢复电量 |
| 取货 | 从相邻货架、装卸口关联车辆或机器人取得货物；自身空载 | 消耗 |
| 送货 | 向相邻货架、装卸口关联车辆或机器人放入携带物；目标可接收 | 消耗 |
| 放下 | 将携带物放入相邻空地面格 | 消耗 |
| 拾起 | 从相邻地面格拾取货物；自身空载 | 消耗 |

取货、送货、放下、拾起具有不同耗电量，具体数值待平衡。所有动作都占用一次行动机会。无动作时机器人保持空闲。

受理通过的意图在结算中失败时，不扣电，但消耗本 tick 的行动机会；受理失败的调用不消耗行动机会。状态查询不消耗行动机会。静态条件（相邻、空载、容量、电量等）在受理阶段以错误码返回，依赖同 tick 其他意图的冲突在结算阶段判定，下一 tick 可查询原因。

## 移动冲突

移动动作的受理只做静态检查（位于界内、目标格在快照中可通行、本 tick 未行动），以下冲突全部在结算阶段判定；受理返回 `"OK"` 后仍可能因这些规则失败。

当前基线：

- 多个机器人争抢同一目标格：全部失败。
- 目标格机器人本 tick 成功离开：允许跟进。
- 两个机器人迎面交换位置：不允许。
- 多个机器人围成一圈同时轮转：允许。
- 移动链的前方机器人未能离开：依赖其离开的后续移动也不能成功。

这些规则保留单行通道、避让区和交通调度的价值，不依赖玩家代码调用动作的先后顺序。

## 机器人间转交

主动取货或送货的一方消耗动作和电力，被动方无须提交接收或交出动作。双方必须相邻，接收方空载，作为交互目标的机器人本 tick 不移动。

同一机器人或货物被多个交互同时引用时，以及被动方同时执行其他非移动动作时，如何处理仍待明确。不可在实现中隐式依靠调用顺序解决。

## 电力与充电

移动不耗电，耗尽电量的机器人仍可移动到充电桩旁边。能否抵达仍受通道占用影响，不保证在任意布局下都可达。

充电占用动作并按 tick 恢复电量。玩家可以空闲补电、在接任务前预估电量，或分批安排机器人充电。电量不足属于受理阶段可判定的失败，动作接口直接返回对应错误码。

首期不引入电池老化和浮动电价。电池容量、充电速率、各动作耗电及充电桩冲突规则见 [待定事项](07-scope-and-open-questions.md)。
