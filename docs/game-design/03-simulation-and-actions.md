# Tick、动作与电力

## 世界结算

已确定以 tick 度量游戏时间，玩家代码同步执行，不支持异步。

当前基线采用“查询状态 → 提交指令 → 统一结算”，动作反馈分受理和结算两层：

1. `loop()` 查询 tick 开始时的世界快照。
2. 玩家为机器人提交本 tick 的动作，每个动作接口立即返回受理结果。
3. `loop()` 正常结束后，系统对全部已受理意图统一校验并结算。
4. 下一 tick 可查询新状态及上一 tick 的结算结果。

调用移动接口后立即读取位置，仍然得到本 tick 开始时的位置。受理通过也不代表最终执行成功，结果以结算为准。

管理操作即时生效（见 [API 设计](08-api-design.md)）。结算顺序基线：车辆出现在 tick 边界、`loop()` 之前，接单后的下一 tick 开局即可查询并交互；机器人动作在结算中清空或装满车辆的同一 tick，结算内依次完成车辆离场、订单完成与收款、装卸位释放，下一 tick 查询全部可见。

## 动作受理与结果码

每个动作接口在调用时同步返回一个字符串结果码：

- `"OK"`：意图通过受理检查，进入本 tick 的统一结算。
- 其他取值：受理失败，字符串字面表达原因，例如 `"NOT_ADJACENT"`（目标不相邻）、`"ALREADY_ACTED"`（本 tick 已有受理通过的动作）、`"LOADED"`（取货时自身非空载）、`"TARGET_FULL"`（目标容器无空位）。最终结果码清单随 API 设计确定。

受理规则：

- 受理检查基于调用时的世界状态——tick 开始快照叠加已生效的管理操作；已受理意图仅用于检查该机器人是否已占用行动机会，不预占共享资源——只判定调用时可知的静态条件，如相邻、空载、容量、电量；不预判只能由同时结算产生的结果，如目标格争抢、移动链受阻、充电桩被同 tick 其他充电动作占用。
- 受理失败不消耗行动机会，玩家代码可在同一 tick 改提其他动作。
- 受理通过即占用本 tick 行动机会，此后对该机器人重复提交动作返回受理错误，不静默覆盖。
- 共享货物、容器空位、充电桩和目标格不在受理阶段预占。例如货架快照剩一个空位，两台机器人提交送货均可受理通过，结算时 id 小者成功。固定世界与管理操作影响后，重排机器人提交顺序不改变受理集合及结算结果。

结算结果查询：

- 每个机器人提供上一 tick 结果查询，返回其受理通过的动作与结算结果码；成功为 `"OK"`，失败原因与受理结果码共用同一词表，如 `"CELL_CONTESTED"`（目标格争抢）、`"CHAIN_BLOCKED"`（移动链受阻）、`"CHARGER_BUSY"`（充电桩被同 tick 充电动作占用）。
- 每机器人每 tick 至多一个受理通过的动作，单个结果槽即可表达；该 tick 未受理通过任何动作时 `last_result` 置为 `None`，不保留历史值。受理失败的结果码调用时已同步返回，不进入该记录。
- 命名见 [API 设计](08-api-design.md) 的 `last_result`，最终字段结构待定。

玩家代码抛出异常或执行超限时：已受理动作与已生效管理操作照常结算，世界推进至 tick 边界后暂停并显示错误，恢复运行后从下一 tick 继续；初始化失败时 `loop()` 未被调用，世界与 Game.memory 原样不动；初始化 memory 使用临时分支，成功后才提交。

## 机器人动作

| 动作 | 目标与条件 | 电力 |
| --- | --- | --- |
| 移动 | 沿上下左右移动一格，满足占位和冲突规则 | 不消耗 |
| 充电 | 相邻充电桩可提供服务 | 恢复电量 |
| 取货 | 从相邻货架、装卸位关联车辆或机器人取得货物；自身空载 | 消耗 |
| 送货 | 向相邻货架、装卸位关联车辆或机器人放入携带物；目标可接收 | 消耗 |
| 放下 | 将携带物放入相邻空地面格 | 消耗 |
| 拾起 | 从相邻地面格拾起货物；自身空载 | 消耗 |

取货、送货、放下、拾起具有不同耗电量，具体数值待平衡。所有动作都占用一次行动机会。无动作时机器人保持空闲。

受理通过的意图在结算中失败时，不扣电，但消耗本 tick 的行动机会；受理失败的调用不消耗行动机会。状态查询不消耗行动机会。静态条件（相邻、空载、容量、电量等）在受理阶段以结果码返回，依赖同 tick 其他意图的冲突在结算阶段判定，下一 tick 可查询原因。

## 冲突裁决

同一 tick 内多个意图竞争同一格、同一货物或同一容器的空位时，机器人 id 小者优先取得候选资格（id 为创建序号，小即更早创建）；候选仍须满足依赖与其他资源条件，其余失败并收到对应结果码（`CELL_CONTESTED` / `TARGET_CONTESTED`）。裁决只依据 id 这类显式规则，与提交顺序无关；id 顺序也因此成为玩家可用的优先级机制——关键任务交给 id 小的机器人。

## 移动冲突

移动动作的受理只做静态检查（位于界内、目标格在快照中可通行、本 tick 未行动），以下冲突全部在结算阶段判定；受理返回 `"OK"` 后仍可能因这些规则失败。

当前基线：

- 多个机器人争抢同一目标格：id 小者取得候选资格，若依赖受阻仍失败，不递补；其余失败（见冲突裁决）。
- 目标格机器人本 tick 成功离开：允许跟进。
- 两个机器人迎面交换位置：不允许。
- 多个机器人围成一圈同时轮转：允许。
- 移动链的前方机器人未能离开：依赖其离开的后续移动也不能成功。

迎面交换与链条依赖仍要求玩家做通道规划与避让；所有裁决不依赖调用顺序。

## 机器人间转交

主动取货或送货的一方消耗动作和电力，被动方无须提交接收或交出动作。双方必须相邻，接收方空载，作为交互目标的机器人本 tick 不成功移动。

多个交互竞争同一货物或空位时按冲突裁决由 id 小者胜出，落败方返回 `TARGET_CONTESTED`；目标机器人同 tick 成功移动则移动照常、转交失败返回 `TARGET_MOVED`；移动失败时按原位置判定转交；被动方充电与转交不冲突；被动方主动取放仍须参加同箱与容量裁决。

## 结算资源与执行顺序

受理不预测其他动作创造的资源：快照中满载的机器人不能因计划交出而再取货，满货架不能因计划取出而预先受理送货。管理操作之后的最终状态用于重新校验已受理动作，失效目标先剔除。

| 组合 | 结算规则 |
| --- | --- |
| 多个 move / drop 争同一落点 | 共同按主动机器人 id 选一个候选；候选后续受阻不递补，本 tick 其他候选失败 |
| 移动链 / 环 | 在落点候选确定后求解离开依赖；二元交换失败返回 `CHAIN_BLOCKED`，长度至少三的环允许，受阻沿链传播 |
| drop 到原有机器人格 | 只有占位机器人成功离开才可执行；否则 `CELL_OCCUPIED` |
| 转交目标移动 | 先确定移动成败；成功离开的目标使转交失败 `TARGET_MOVED` |
| 同箱、多方取放、容器容量 | 剩余非移动动作按主动机器人 id 升序原子占用货物和容量；资源已消耗则 `TARGET_CONTESTED`，整条动作无部分效果；同一箱每 tick 最多转移一次，不允许在不同动作间接力 |
| 被动机器人同时主动取放 | 被动收取也占其单箱容量，被动交出也占其货物；主动与被动请求进入同一资源裁决，不得重复移交一箱或使机器人超载 |
| 已受理动作的主体或目标被管理操作删除 | 动作失败 `TARGET_GONE`；主体已删时结果保留在诊断事件中 |
| 充电与转交 | 充电只改变电量，不占货物资源；转交耗电按结算前电量校验，不提前使用同 tick 充入电量 |

先在最终管理状态上做重新校验，再确定 move/drop 落点候选及移动依赖，最后按上述规则模拟资源变化；全部成功动作一次发布到下一世界状态。候选失败不递补使规则保持确定且可解释。管理操作的插入或重排仍可能改变结果，不属于机器人提交顺序无关的承诺。

## 电力与充电

移动不耗电，耗尽电量的机器人仍可移动到充电桩旁边。能否抵达仍受通道占用影响，不保证在任意布局下都可达。

每次 `charge()` 只申请一个 tick 的充电，下一 tick 须重新提交；没有跨 tick 的充电锁定或自动续充。相邻多个充电桩时选择 id 最小的桩，不自动尝试其他桩；同 tick 竞争由机器人 id 裁决。充电占用动作并按 tick 恢复电量。玩家可以空闲补电、在接任务前预估电量，或分批安排机器人充电。电量不足属于受理阶段可判定的失败，动作接口直接返回对应结果码。

首期不引入电池老化和浮动电价。充电桩选择以调用时状态固定为目标 id，之后目标被销毁则失败，不自动换桩。电池容量、充电速率、各动作耗电的数值见 [待定事项](07-scope-and-open-questions.md)。
