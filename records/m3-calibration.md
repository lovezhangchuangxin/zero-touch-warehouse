## 基准场景与方法

  装卸位、六货架、双充电桩、**两台机器人**（分区作业：0 号西装卸位

- 窗口：600 tick × 3 个世界种子（20260913 / 7 / 41277，同一地图与市场
  参数、只换种子——平滑单窗口行情运气）。
- 代表脚本（web/apps/game/src/scripts/demos/，编辑器示例同一份文本）：

| 脚本 | 策略 | 买卖门（相对中枢） |
| --- | --- | --- |
| demo_trade_fast.js | 快转：只做 water，紧门快进快出 | water 买 0.93 / 卖 1.03 |
| demo_trade_hoard.js | 囤货：三货物深门低吸高抛，货架为主 | battery 0.89/1.10、chip 0.84/1.13 |

中枢估计 = 两侧挂单均值的慢速 EMA（0.5%/tick，约 200 tick 记忆）；
买卖门深度按「毛利 = 卖门 / 买门 − 1」配对到 docs 09 目标带。

## 指标定义（全部以 milli 权威值计算，展示折算 gold）

- 库存成本值 = Σ 各型现存箱数 × 该型历史买入均价（移动加权）
- 占用资金 = 金币 + 库存成本值；资金周转率 = 收款总额 / 平均占用资金 /（tick/100）
- 囤货占用率 = 平均库存成本值 / 平均占用资金
- 净利润 = Σ 窗口（终态金币 + 终态库存成本值 − 终态欠款 − 初始金币）
- 停摆刻度 = 首个「金币 < 最便宜整单成本 且 欠款 ≥ 信用额度」tick（无则 N/A）
- 分货物毛利 = 已售均价 / 历史买入均价 − 1
- 完成口径：订单离开 my_orders 即视为成交——本套脚本不调用 market.cancel

## 结论与取舍

1. **周转与囤货取舍成立**：快转占用率 10% 但收款与利润最薄（+3.0）；
   囤货以 14% 占用换 8 倍利润（+24.3）；杠杆把占用推到 39% 并放大交易
   频次（11 单），但期末 349 gold 库存 + 254 gold 欠款使账面利润为负
   ——库存按成本计价、波段未平，利息在滚动，是设计中的自选风险而非
   失衡。三策略均无停摆。
2. **毛利带确认**：water 落在下沿（+10%，门配对 1.03/0.93 = +10.8%
   的设计值）；chip 实测 +45% 入 30%–50% 带。battery 在本窗口组无完成
   卖出（买在 12.80 低位、等待回归），配对设计值 +23.6% 在带内，留待
   后续窗口确认——按设计值冻结，不改参数。
3. **吞吐是硬顶**：两台机器人 600 tick 约 50–60 箱取放量，快转的
   「高频」被物理吞吐限制（这正是「装卸位机会成本」的设计意图）；
   提频靠加机器人（商店购买，游戏内可行）。

## 校准过程中暴露并修复的市场模型问题（工程结论）

1. **对侧极值钳制钉死板面**（期 1 设计缺陷，校准实测暴露）：新挂单被
   旧 max_bid × 1.12 抬价后，基准价涨跌传不到板面。改为「围绕当前线
   采样 + 交叉时撤较旧者」的修复语义（marketgen.rs）。
2. **时代错位病理**：旧低价 bid 与新高价 ask 共存把板面价差拉到 60%+，
   任何卖出门永不可及。修复：刷新时清除偏离当前理论线 ±20% 的滞留
   报价（板面维护，非玩家侧撤单风险）+ 每轮半板换手；不变量测试补
   「板面跟踪」断言（价差率 ≤ 65%）。
3. **极值中枢被自身行为偏移**：策略吃掉最便宜 ask 会抬高 (min_ask+
   max_bid)/2 中枢，改为两侧均值。
4. 脚本侧四个物流死锁（暂存迷宫、容量门符号错、货架箱不计库存、
   满仓 return 跳过卖出扫描）与一个移动死锁（贪心对穿横跳，加绕行
   方向记忆）——均为代表脚本的工程问题，非引擎问题；引擎侧全程无
   违反不变量。

## 评审复核（同日重跑，数字不变）

三路 subagent 评审（sim 层 / api+绑定层 / 测试+校准产物）后修复以下工程
缺陷并全量重跑基准：三策略数字与上表逐项一致（修复只影响这些种子未
触发的路径）——

- 采集器：停摆刻度此前被窗口收尾清空、跨窗口断言恒真；现保留并在合并
  时取最早，「杠杆无停摆」的验收恢复效力。
- 脚本：容量门改按全货物在途总量扣减（暂存格不分货物，跨货物不重复
  计入余量）；取货扫描补对侧分区暂存兜底；价格中枢注释与「两侧均值」
  实现对齐；快转落位注释与实际行为对齐。
- 引擎：dock 购买补锚点格占位校验（设施 → CELL_BLOCKED、地面货物 →
  CELL_OCCUPIED，与第二格检查对称）；资金入账统一 saturating_add。
- 绑定：bootstrap.py 大整数金额（10**400 级）float 溢出从抛异常改为
  拒绝（JS 同输入返回 INVALID_ARGUMENT，双语言位级一致）；结果码五处
  同步点（codes::ALL ↔ 两份 bootstrap E ↔ GameCode ↔ web codes.ts）补
  机械对账测试。
